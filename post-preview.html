一句话：把 git log 变成一张 1024 年度海报——24 小时提交钟面、星期分布、段位徽章，外加一份给 commit message 开的「病历本」。纯前端、零依赖、双击即开、离线可用，数据全程不离开你的浏览器。

在线体验：代码年轮 · Code Tree Rings 源码：github.com/942740052/code-tree-rings

这到底是什么

一个纯前端网页。粘贴一段 git log 输出，它在你本地解析，然后画出一张可以收藏、可以发群的年度海报。

它不是一张静态图，是能点的：

  • 24 小时提交钟面 —— 圆环上每一根刺是一个小时，越长提交越多，峰值小时高亮
  • 星期分布 —— 一周里哪天最能写，周末单独配色
  • 段位徽章 —— 2⁰ → 2¹⁰ 共 11 级，从「Hello, World」一路到「2¹⁰ · 满级 Builder」
  • Builder 指数 —— 0–100 的健康度综合分：活跃度 / 连续性 / 作息 / 命名，四维加权
  • commit message 病历本 —— 敷衍指数、病情分级、病种构成，以及「最该被枪毙的那条」
  • 导出 PNG —— 2400×3200，2 倍分辨率

海报只由一张 Canvas 绘制，页面里看到的就是导出结果，不存在「所见非所得」。

三套配色：终端绿 / 暖阳 / 极简黑白。

30 秒怎么玩

  1. 打开上面的链接（或直接下载 index.html 双击打开）
  2. 点「复制命令」，在自己的仓库目录粘贴执行；也可以点「载入示例年度」
  3. 把输出粘进文本框，点「生成我的年轮」
  4. 点「导出 PNG」，2400×3200，保存下来发群

不知道仓库目录在哪？ 展开「不知道仓库目录在哪 / 不会用命令行？点这里 →」，里面有一条能自动列出你电脑上所有 git 仓库的命令，复制到终端跑一次就知道该 cd 去哪了。

没有 git 也能玩：展开「手动填数模式」，填提交数 / 活跃天数 / 连续天数 / 最常时段即可出图。

病历本：它会怎么毒舌你

这是我最喜欢的一块。它按 11 条规则给你的 commit message「会诊」：

病种触发词举例
急性半成品综合征wip
键盘随机游走症asdf qwer test
极简主义绝症1 . 。
修补依赖症fix 修复 改bug
修改失语症update 更新 修改
职场真实症摸鱼 下班 删库
情绪性提交orz 救命 崩了
最终版妄想症（晚期）最终版 final

敷衍指数用 1 − e^(−density/2.2) 的指数衰减模型算出来（0 最健康，100 最病），再分五级：健康 / 早期 / 中期 / 晚期 / 已列入 1024 纪念册。

「最该被枪毙的那条」会挑出你历史上最敷衍的那句 commit —— 但纯符号和单字符不参与竞选，毕竟拿一个「.」出来甩锅没有说服力。

技术实现（纯前端）

单文件 HTML，无框架、无 CDN、无后端、无第三方库，file:// 下完整可用，87 KB。

  • 解析器：按行状态机，依次尝试「git 默认格式 → numstat → 自定义 format 头 → 缩进消息体 → --oneline → 续行兜底」；分隔符容忍 | , ; Tab，subject 含分隔符时保留，CRLF / 二进制 - / 重命名 a => b / 注释行 / 空行全部容错，上限 20000 条截断
  • 中文路径还原：git 默认把非 ASCII 路径转义成八进制（prd/\346\200\273...），解析器逐字节还原成真实中文文件名
  • 编码兜底：自动识别 UTF-16LE / UTF-16BE / UTF-8 BOM —— Windows 的 > 重定向写的是 UTF-16，粘进来不再满屏乱码
  • 统计层：24 小时 / 星期 / 动词 / 文件四类分桶；最长连续提交用「排序日期 + 相邻差 1 天」线性扫描
  • 渲染层：Canvas 2D，海报是唯一真相源，页面里看到的就是导出结果
  • 导出：离屏 Canvas scale(2,2) 重绘 + toBlob，2400×3200 PNG
  • 隐私：全部计算在浏览器内，零网络请求；排行榜只存本地 localStorage

TRAE 在创作中做了什么

这次几乎全流程都是我和 TRAE 一起完成的：

  • 解析器：git log 三种时间精度的格式兼容、git 默认格式的 commit / Author: / Date: 状态机、numstat 含二进制与重命名的归一化、分隔符容忍与 subject 切分策略
  • 统计口径：活跃天数、跨度、深夜指数、周末战士指数、最长连续提交的算法，以及 Builder 指数的加权公式
  • 海报设计：1200×1600 竖版布局、24 小时极坐标钟面、星期条形图、动词 Top5 横条、病历本面板排版与三套配色
  • 病历本规则：11 条规则的词表与权重设计，以及 1 − e^(−density/2.2) 的指数衰减模型和校准
  • 交互：拖放读文件、示例数据生成器、时间筛选、本地排行榜、导出与降级兜底
  • 自测：49 条断言的用例设计与边界值选取

最有意思的不是写功能，是把「看起来对」变成「验证过对」。

海报排版第一版底部徽章和结尾文字是重叠的 —— 纯读代码看不出来，是靠无头 Chrome 批量出图 + 逐像素采样才发现的。同类问题还有两个：自己的真实仓库跑出来，「最常改的文件」全是 \346\200\273 乱码（一查才知道是 git 的 quotepath 转义），以及 Windows 的 > 重定向写 UTF-16 导致只解析出 7/15 条提交。

这三个坑都不是读代码能发现的，是拿自己的真实仓库跑一遍才暴露的。所以现在解析器把这类情况都兜住了，断言也从最初的 41 条加到 49 条。

关键提示词

这个作品最初的想法，就是几句话聊出来的：

「我想弄一个年度总结那样的东西，把我的 git log 变成一张海报，最好能晒出去。」
「不要任何依赖，就一个 HTML 文件，双击就能开，断网也要能用。」
「数据千万不能传到任何地方，要全程留在浏览器里，不需要 token，不需要授权。」
「提交数凑到 1024 就满级，段位从 2 的 0 次方排到 2 的 10 次方。」
「commit message 也要玩一下，给我一个敷衍指数，再评个病情，顺便告诉我哪条最该被枪毙。」

一些数字

  • 输入格式支持：5 种（自定义三种精度 / 默认格式 / oneline）
  • 分隔符容忍：4 种

  • 海报尺寸：1200×1600，导出 2400×3200
  • 配色：3 套
  • 病历规则：11 条

  • 网络请求：0
